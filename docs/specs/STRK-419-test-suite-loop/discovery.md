## External References

- [Playwright `Coverage` class](https://playwright.dev/docs/api/class-coverage):
  `page.coverage.startJSCoverage({ resetOnNavigation })` / `stopJSCoverage()`, Chromium only.
  Returns V8 function ranges as character offsets per script URL, with `source`.
- [Playwright sharding](https://playwright.dev/docs/test-sharding): `--shard=i/n`, `blob`
  reporter per shard, `npx playwright merge-reports` to combine.
- [monocart-coverage-reports](https://github.com/cenfun/monocart-coverage-reports): adds V8
  coverage per process into a cache, merges across processes (`inputDir`), filters by
  `entryFilter`/`sourceFilter`, writes `lcov`/`lcovonly`, has a Codacy example.
- [codacy-coverage-reporter-action](https://github.com/codacy/codacy-coverage-reporter-action)
  and [codacy-coverage-reporter](https://github.com/codacy/codacy-coverage-reporter):
  `project-token`, comma-separated `coverage-reports`, `--partial` uploads closed by a final
  call.
- Node `--experimental-test-coverage --test-reporter=lcov`: attributes coverage by module
  URL, so code evaluated through `new Function` is not attributed to its file (measured
  above).

## Constraints

- Zero build, zero install for the app. Test tooling may add dev dependencies; the app
  must not load them.
- Script-tag globals: there is no import graph from `js/` files to tests. File-to-test
  mapping can come only from runtime coverage or from text references.
- Every core test boots the full app; boot cost is fixed at about 0.35 s per boot on the
  reference machine.
- Codacy coverage and quality-gate settings live outside the repo. The coverage
  "must not drop" rule and the new required check are dashboard and ruleset changes the
  user makes.
- `CODACY_PROJECT_TOKEN` must be created in Codacy and stored as a GitHub Actions secret by
  the user (repository API token; never in a config file).
- The `dev` ruleset requires signed commits and merge-only; CI must not push.
- The template master lives in `Devops` on the home Gitea (commit straight to `main`); the
  StakTrakr copies change only through `skills-deploy` and a chore PR.
- Codacy duplication is a merge gate: consolidated test setup must go into shared helpers.
- Public repo: no internal hosts or LAN addresses in workflows or docs.
- PR 1621 must merge first; this spec builds on its config and fixture.

  every shard and whether the local map rebuild is practical.
- Mapping changed lines to V8 function ranges needs a line-to-offset conversion against the
  served source of the same commit.
- Where the coverage map lives (committed file, CI artifact, or local build) decides how
  AC-18 detects staleness.
- GitHub-hosted runner size for this public repo, and the shard count needed for the
  10-minute CI budget.

## Discovery Summary

The work lands in `playwright.config.js`, the shared fixture in
`tests/playwright/helpers/mocks/extended-test.js`, a new CI workflow, new `devops/` scripts
for the map and report, `package.json`, the core specs and the template master in
`Devops/skill-library`. Boot cost is fixed, so the 3-minute target depends on removing boots:
about a third of core tests look logic-only, mostly in six files. The tricky parts are unit
coverage (Node cannot attribute `new Function` code) and changed-line-to-function mapping;
the CI job, Codacy upload and archive removal are routine.
