# Implementation Log: Task 8 — Wire initMarketData into App Startup

## Task
Wire `initMarketData()` into the app startup sequence in `js/init.js` and add theme change handling.

## Changes Made

### `js/init.js`
- Added fire-and-forget `initMarketData()` call after exchange rates fetch (line ~615), before Phase 14 event listeners
- Added `MutationObserver` on `document.documentElement` watching `data-theme` attribute changes to trigger `refreshMarketData()` on theme toggle
- Both calls guarded with `typeof` checks so app works if `market-data.js` fails to load
- `.catch()` on initMarketData prevents unhandled promise rejections

## Design Decisions
- Used `MutationObserver` for theme detection rather than modifying `theme.js` — `setTheme()` modifies `data-theme` attribute on `<html>`, so observing attribute changes is clean and non-invasive
- Observer fires on both `setAttribute` (dark/sepia) and `removeAttribute` (light), covering all theme transitions
- Placed init call after spot price fetch + exchange rates but before event listener setup — market data needs spot prices available

## Verification
- `node -c js/init.js` passes
- No modifications to any file besides `js/init.js`
- No `console.log`, no raw `document.getElementById`, no direct `localStorage` usage
