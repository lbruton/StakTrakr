# STRK-52 — Approach

_How we'll build it. **Don't write code or tests** — the tasks phase produces the work plan._

## High-Level Architecture

The fix is surgical and confined to three lexical regions of `js/catalog-api.js`: the tag-picker render (lines 1856–1978), the bulk Check/Uncheck-all handlers (1967–1977), and the Fill Fields submit handler (2377–2403). No new files, no localStorage schema change, and no edits to the tag-storage primitives in `js/tags.js`. The only test file touched is `tests/playwright/numista-picker-tags.spec.js`.

The control plane is a single new dataset attribute, `data-on-item="1"` (read in JS as `cb.dataset.onItem`), placed on the tag-row checkbox at render time when the existing `isOnItem` predicate is true. Two later handlers consume that attribute: (a) bulk Uncheck-all skips checkboxes carrying it (AC-9 / AC-10), and (b) Fill Fields treats a now-unchecked checkbox carrying it as an explicit user opt-out, which triggers the existing `removeItemTag()` path (AC-3). `removeItemTag()` already records the opt-out through `addRemovedTag()`, so submit code should not call `addRemovedTag()` a second time. Re-checking a previously-removed tag continues to use the existing `clearRemovedTag` flow at lines 2393–2402 (AC-7). Manual-only tags never enter the picker at all (AC-4) because the iterator at line 1872 only walks the Numista result; that behavior is preserved unchanged. AC-5 (one logical tag for matching manual + Numista text) is satisfied incidentally by the current case-insensitive `isOnItem` predicate at line 1912 and requires no new code — only a regression test to lock it in.

The one behavioral subtlety lives in the case-insensitive removal path (AC-6). `removeItemTag()` at `js/tags.js:123–145` removes by exact-string match. Rather than patch the primitive — which has callers throughout the inventory UI — the Fill Fields handler resolves the case mismatch locally: before calling `removeItemTag(uuid, ...)`, it looks up the user's actual stored casing via `getItemTags(uuid)` and passes that exact string. `removeItemTag()` then calls `addRemovedTag()` internally, which capitalizes on store and matches the existing storage contract.

## Tradeoffs Surfaced for Review

- **Case-insensitive removal scope (D-3).** Resolving AC-6 locally inside the Fill Fields handler vs. patching `removeItemTag()` to be case-insensitive globally. Local resolution keeps blast radius to one call site; a global patch would close the door on the same bug recurring elsewhere. Default is **local**; flag for user input before tasks if the global fix is preferred. (If user picks global, that becomes a one-line behavior change to `js/tags.js:123–145` and the local re-lookup goes away.)
- **Visual marker shape (D-4).** Default is the plain-text "(on item)" hint, mirroring the existing "(blacklisted)" hint. Requirements §Non-Goals §6 permits chip/pill styling but does not require it. If user prefers a small CSS-only badge instead, the cost is a single CSS rule plus a wrapper `<span class="on-item-pill">` around the hint — still a one-line change, no layout shift. Easy to upgrade later if plain text proves too easy to miss in user testing.
- **Test rewrite framing (D-5).** Test 3 currently encodes the wrong spec. The rewrite is legitimate spec correction, not TDD bypass — but the PR description must say so explicitly (cite STRK-52 as the spec correction) to avoid reviewer confusion or a hookify-rule false-positive read. Tasks.md must include a Cohort 0 note: do not toggle the hook if it fires.

## Out of Scope (follow-up issues)

- **Possible follow-up: make `removeItemTag()` case-insensitive globally.** Today only the Numista submit path is at risk. If another caller surfaces the same bug (e.g. a future "import tags from clipboard" flow), file a separate STRK issue and resolve at the primitive. Not bundled here to keep blast radius small.
- **Already excluded by Non-Goals (locked in requirements):** per-tag source/provenance metadata, rendering manual-only tags in the Numista picker, broader modal layout overhaul, changes to global auto-apply / blacklist concepts beyond what AC-1 / AC-3 require, bulk metadata sync changes outside the user-facing picker.

## Risk Notes

- **Risk:** Bulk Uncheck-all needs **both** `!cb.disabled` and `!cb.dataset.onItem` guards; missing either drops AC-10 (blacklisted protection) or AC-9 (on-item protection). → **Mitigation:** Cover both protections with a single Playwright test that mixes blacklisted, removed, new, and existing-on-item rows in one modal and verifies Uncheck-all preserves both classes simultaneously.
- **Risk:** The Fill Fields submit walk runs after the checked-tag application path in the existing handler. If checked-tag application mutates item tags such that `getItemTags(uuid)` returns a different list than at render time, the case-lookup could miss its target. → **Mitigation:** During implementation, inspect the order of operations end-to-end. If checked-tag application mutates in a way that loses the original casing, snapshot item tags into a closure at render time and pass that snapshot into the submit walk instead of reading fresh. Tasks.md should call this out as a verification step.
- **Risk:** `data-on-item` attribute name collides with an existing dataset key elsewhere in the codebase. → **Mitigation:** A `grep -r "dataset.onItem\|data-on-item" js/` check before naming finalization, called out as a tasks.md prerequisite. Cheap, keeps a future debugging hour out of the budget.
- **Risk:** Hookify `block-tdd-test-modification` fires on the Test 3 rewrite and the agent toggles it off to land the change. → **Mitigation:** Per CLAUDE.md's global TDD rule (§ "TDD Test Integrity — RED FLAG"), hookify firing is a **halt-and-explain** signal — not a permission gate. Tasks.md must instruct: do **not** disable, suppress, or coach around the hook to land the test edit. If it fires, surface the spec-correction framing to the user, get explicit user approval to proceed, and document that approval in the PR description. The user can then approve the test rewrite as a one-time exception.
