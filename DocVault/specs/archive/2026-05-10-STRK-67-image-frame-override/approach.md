# STRK-67 — Approach

_How we'll build it. **Don't write code or tests** — the tasks phase produces the work plan._

## High-Level Architecture

The work has three layers and a glue layer:

1. **One synchronous resolver, three call sites — applied per slot, not per item.** A new bare module `js/image-frame.js` exports `resolveImageFrame(item, side) → "round" | "rect"` and `cycleFrame(value) → "auto" | "circle" | "rectangle"`. Both functions are exposed on `window` (StakTrakr convention; no build step). The three current shape predicates — `_isRectThumb` (`inventory-table.js:512`), `isRect` (`card-view.js:550`), and `isRectShape` (`viewModal.js:255`) — collapse to calls into the resolver, but with a structural change: the table currently applies one `_thumbShapeClass` to both sides and the view modal applies `view-shape-rect` at `#viewImageSection` (whole-section). To support per-side overrides (AC-11), shape decisions move to the per-slot level — each rendered thumbnail / each `.view-image-slot` calls the resolver independently. Card view is already per-side. The resolver implements AC-1 through AC-6 in priority order: explicit override wins; then type-based; then `gradingAuthority` non-empty; then `classifyShape(numistaData?.shape) !== "round"`; then round. No async work, no IDB lookups, no shape flash beyond the existing late-Numista-enrichment case (which keeps the safety net at `viewModal.js:1173`, now updated to toggle classes both ways — see D-3).

2. **Modal pending-state mirroring the existing image-blob pattern.** `js/events.js` already carries `_pendingObverseBlob` / `_pendingReverseBlob` and friends as module-scoped session state for the Add/Edit Item modal. Two new variables `_pendingObverseFrame` / `_pendingReverseFrame` ride the same lifecycle: initialized on modal open (from `inventory.js:editItem`), mutated by the toggle click handler, swapped by `#swapImagesBtn` (per AC-13), reset to `"auto"` by the Remove button (per AC-15), threaded into `parseItemFormFields` → `buildItemFields` → `commitItemToInventory` on save. The toggle DOM element is a static button in `index.html` placed inside `.image-upload-preview` (Variant A from the artifacts), wired by a single click handler in `events.js`.

3. **Persistence + cloud sync via the STAK-493 dual-list update.** Both fields get added to `DIFF_FIELDS` (`diff-engine.js`) AND to `logItemChanges`'s field array (`changeLog.js`) AND to the JSDoc typedef in `types.js` — three edits in lockstep, treated as one indivisible work unit. `loadInventory` and `sanitizeImportedItem` deliberately do **not** stamp `"auto"` on absent fields (AC-10). On save, when the value is `"auto"`, the field is omitted from the persisted object (decision D-2 below) so cloud-sync diffs and undo/redo stacks stay clean for legacy items. The save path **explicitly deletes** any pre-existing `obverseImageFrame` / `reverseImageFrame` from the merged item when the user's choice is `"auto"` — without this delete, `commitItemToInventory`'s `{ ...oldItem, ...buildItemFields(f) }` merge would silently preserve the old value (decision D-11 below).

The glue layer is a small AC-14 enabler: a debounced `input` listener on `#itemObverseImageUrl` / `#itemReverseImageUrl` that toggles the corresponding `.image-upload-preview` between hidden and visible based on whether the typed URL matches `/^https?:\/\/.+\..+/i` and the resulting `<img>` decodes successfully. This is the precondition that makes US-4 (URL-pasted slab override) reachable in a single modal session — without it, the Frame toggle stays hidden until the user saves and reopens.

> CODEX: D-1 looks like the right architectural home. A tiny pure `js/image-frame.js` is cleaner than pushing display-policy rules into `catalog-api.js`, as long as it stays DOM-free and load-ordered after `classifyShape`. I would keep this decision.

> CODEX: D-2's "absent ≡ auto forever" read contract is defensible for the current enum and does not trap a future `landscape`/`portrait` expansion, because those can be explicit values while absence remains the default resolver path. The only future thing this gives up is distinguishing "legacy never touched this control" from "user intentionally selected auto"; that seems acceptable for this sketch, but the write path needs special handling on edit so clearing an existing explicit value back to `auto` actually deletes/overwrites the old property rather than leaving it behind through the `oldItem + buildItemFields(f)` merge.

> CODEX: D-3 is worth keeping only if the late path is a setter, not an add-only patch. Current code adds `view-shape-rect` when late Numista data is non-round; after overrides exist, the late path must call the resolver and then `toggle`/set the class both ways, otherwise an explicit `circle` override or a side that resolves round can be silently flipped/stuck rectangular.

> CODEX: D-6's debounced `input` tradeoff is reasonable; I would not switch this to `blur` because that makes URL-pasted slab override feel broken until focus leaves. The implementation should still use a stale-load guard/generation token so an older `<img>.error` or `<img>.load` cannot hide/show the preview after the user has already typed a newer URL, and the regex should be treated as a first gate rather than the whole safety story.

> CODEX: D-7 is the right call, but the test wording should verify the rendered card image's actual `object-fit` result for both resolver outcomes. An inline-style assertion alone is a little brittle if implementation moves that value into a CSS class later; computed style plus the wrapper class would defend the behavior more directly.

> GEMINI: For D-8 (Toggle defaults): Verify that `--metal-gold` reads cleanly against the dashed drop-zone background in all three themes (light, slate/blue-gray, dark navy, sepia). Also, for color-blind users, the glyph itself (`A` / `○` / `▭`) provides the primary distinction, but ensure the muted vs gold hue shift isn't the *only* indicator of "override active" state.

## Data / Schema Changes

Two new optional scalar string fields on inventory items:

- `obverseImageFrame?: "auto" | "circle" | "rectangle"`
- `reverseImageFrame?: "auto" | "circle" | "rectangle"`

**Default semantics:** absent ≡ `"auto"` ≡ "resolve via auto rule (AC-3 → AC-4 → AC-5 → AC-6)".

**Backfill:** none. Per AC-10, `loadInventory` and `sanitizeImportedItem` MUST NOT stamp `"auto"` on absent fields. The first time a user saves an item through the new modal, the fields are persisted with their then-current values (subject to the D-2 omit-when-`"auto"` rule).

**Round-trip surface:** ZIP backup carries them automatically (whole-array JSON blob). Cloud sync carries them via the dual-list update on `DIFF_FIELDS` + `logItemChanges`. CSV export does not carry image data and remains unchanged.

## Tradeoffs Surfaced for Review

- **D-2 omit-when-`"auto"` persistence rule.** Alternative: always persist explicit `"auto"` once the user touches the item (mirrors how some other StakTrakr fields normalize on load). Choosing omit-when-`"auto"` keeps cloud-sync diffs lean for the common case where users never touch the override, but it means readers must forever treat absent and `"auto"` identically. Surfacing because it's a design contract, not a local detail.
- **D-3 keep-the-late-override.** Could go the other way and delete `viewModal.js:1173-1180` entirely; the synchronous resolver covers the common case. Keeping it costs ~8 lines of redundancy but defends against the rare async-Numista-enrichment first-paint flash that already exists today. Surfacing because it's the kind of "preserve existing safety net" call that benefits from a second pair of eyes before tasks.md commits.
- **D-6 debounced `input` vs `blur` for AC-14 live preview.** The behavior is genuinely user-visible: debounced `input` shows the preview while the user is still in the URL field, `blur` waits for tab-out. The CODEX comment in requirements.md was non-committal. If user feedback during implementation favors `blur`, the swap is small.
- **Single-button cycle UI (Variant A) vs explicit 3-button row.** Resolved during requirements (artifacts/variant-a-in-modal.html confirms the choice) but flagged here so reviewers know it was considered and the alternative is documented. Cycle is more compact at the cost of one extra click to reach `rectangle` from `auto`.

## Risk Notes

- **STAK-493 regression** if `DIFF_FIELDS` and `logItemChanges` are split across cohorts or commits. Mitigation: tasks.md treats both edits + the JSDoc typedef as **one indivisible task** in the same Sprint Cohort. Test: a Playwright sync round-trip asserts both fields survive a remote-merge simulation.
- **Card view `object-fit` divergence** if D-7 is forgotten. Mitigation: dedicated test asserts `<img>.style.objectFit === "contain"` whenever `resolveImageFrame` returns `"rect"` for that side, and `"cover"` whenever it returns `"round"`. Tasks.md will list this assertion explicitly under the card-view test task.
- **Frame swap silently corrupting overrides** if the `#swapImagesBtn` handler is not extended (AC-13). Mitigation: dedicated test that sets `obverseImageFrame=rectangle`, `reverseImageFrame=circle`, swaps, asserts the values flipped, and asserts both toggle button faces re-rendered. This test is the trip-wire — it fails loudly if a future refactor reverts the swap handling.
- **Remove not resetting frame** (AC-15) leaving stale preferences haunting a slot. Mitigation: dedicated test that sets a non-`"auto"` override, removes the image, re-uploads, asserts the frame is `"auto"` AND the toggle button face shows `auto`.
- **Script load order** for `js/image-frame.js`. If accidentally placed before `catalog-api.js`, `classifyShape` is undefined when the resolver runs. Mitigation: tasks.md pins the script tag's exact insertion point in `index.html`.
- **`.image-upload-preview` missing `position: relative`** is a one-line CSS edit that, if forgotten, sends the absolute-positioned toggle to the wrong ancestor. Mitigation: explicit task; visual smoke test in the toggle's first Playwright case.
- **Issue body drift** — STRK-67's Plane body still describes the rejected v1 fix. Mitigation: out-of-scope task above; no implementation risk if reviewers read the sketch instead of the issue body.
- **Per-side scaffold incomplete (D-10)** — if C.1 (table) or C.3 (view modal) lands the resolver call but does NOT actually move the class to per-slot, AC-11 silently fails for the mixed-side case (`obverseImageFrame=rectangle` + `reverseImageFrame=circle`). Mitigation: F.1 includes a dedicated mixed-side test that fails loud if either view collapses to one class; the test is the trip-wire.
- **Persistence merge bug (D-11)** — if D.6's explicit-delete is omitted, `commitItemToInventory`'s `{ ...oldItem, ...buildItemFields(f) }` merge silently preserves the old explicit value when the user cycles back to `"auto"`. UI shows the toggle as `auto`, disk still has `"rectangle"`. Mitigation: F.1 includes a test that sets an explicit override, saves, reopens, cycles back to `"auto"`, saves, and reads the persisted item to assert the field is gone — directly defends against the regression.
- **Late-override one-way toggle (D-3)** — if `viewModal.js:1173` continues to use `add` instead of `toggle`, an explicit `circle` override on a non-round Numista item gets stuck rectangular after late enrichment. Mitigation: tasks.md C.3 acceptance line names `classList.toggle(class, condition)` explicitly; F.1 includes a test for `obverseImageFrame=circle` + non-round `numistaData.shape` rendering round in the view modal post-enrichment.
- **Stale URL-load race (D-6)** — without the generation token, an older `<img>.error` callback can hide the preview after the user has typed a newer working URL. Mitigation: F.1 includes a rapid-typing test (two URLs in quick succession) asserting the second URL's outcome wins.
- **Accessibility regression** — D-12's `aria-pressed` / `aria-label` and D-13's expanded touch target are easy to forget under time pressure. Mitigation: tasks.md A.2/A.3/D.2 acceptance lines name each attribute and the pseudo-element explicitly; CLOSE-2 (Codacy CLI) catches missing aria attributes in a static-analysis pass.
