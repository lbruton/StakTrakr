## Audited docs

### `.context/deep-dives/api-reference.md`

STATUS: DRIFTED (structural)

- Claim: "v2 publisher generates endpoints alongside v1. Frontend migration behind
  `USE_V2_API` feature flag (default `false`)."
- Actual: `USE_V2_API` no longer exists in `js/constants.js`; v2 shipped default in
  STAK-506 and v1 was removed from frontend code in STAK-509 (v3.33.92). All frontend
  fetches target `data/v2/` (`js/constants.js:563-564`, `js/api-health.js:156`; zero
  `data/api/` references in `js/`).
- **Nuance the reviewer missed:** `run-publish.sh:51` still invokes the v1 exporter
  (`api-export.js`) before `api-export-v2.js`, so v1 files ARE still published — they are
  legacy-published, not removed. The rewrite says "still written, not consumed", not
  "removed".
- Fix: doc restructured v2-first; v1 demoted to an explicit "Legacy v1 API — still
  published, not consumed" section; vendor-roster note added (mintbuilder et al. now
  exceed the original 7; authoritative roster = `data/v2/providers.json` + the four
  vendor maps).

### `.context/deep-dives/health-checks.md`

STATUS: DRIFTED (script + phrasing)

- Claim (Quick Health Check script): fetches v1 endpoints (`data/api/manifest.json`,
  `data/api/goldback-spot.json`) and gates goldback at `age <= 1500` minutes (25 h) on
  `scraped_at`.
- Actual: goldback staleness is envelope-driven — `stale_after: 7200` s (120 min) in the
  live `data/v2/goldback/latest.json` envelope (verified live:
  `{v, generated_at, stale_after, data:{t, ts, g1_usd, denominations, source}}`);
  25 h died with STRK-248.
- Fix: script rewritten to fetch v2 endpoints and compute staleness from each envelope's
  own `stale_after` — no hardcoded thresholds. `USE_V2_API` phrasing in the v2 Health
  Check Path section updated (flag removed in STAK-509; `api-health.js` always reads the
  envelope; STRK-331 freshest-`generated_at` rule noted). Diagnosing-table manifest rows
  repointed to `v2/manifest.json`.
