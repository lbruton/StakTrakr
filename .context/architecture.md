## System Overview

StakTrakr is a **precious metals inventory tracker** with three distinct layers:

1. **PWA frontend** — single HTML page, vanilla JS, no bundler, `localStorage` persistence, runs on `file://` or HTTP
2. **Dual-poller backend** — Home VM (retail + goldback scraper) and Fly.io thin publisher (spot poller + data export)
3. **API layer** — static JSON files generated by the publisher and served via GitHub Pages at `api.staktrakr.com`

There is no dynamic server. The frontend is a pure consumer of static JSON feeds. All user inventory data lives in the browser.

> **Goldback badge freshness (STRK-257).** Envelope `generated_at` is **always** the
> normalized `scraped_at` — `resolveGoldbackGeneratedAt()`
> (`devops/pollers/shared/api-export-v2.js:894-920`, used at `:948-960`) falls back to
> publish time only when no usable scrape timestamp exists. So the badge tracks the scrape,
> not the publish cycle, and it reads roughly the scrape age rather than "~2m". An unchanged
> `g1_usd` across publishes is still normal — goldback.com's upstream rate (`data.t`) can lag
> — but the timestamp no longer refreshes with it.

## Frontend Architecture

### Runtime Model

StakTrakr is a **single-page application** — one `index.html` containing all panels, modals, and sections. No framework, no bundler, no build step. The runtime artifact is the raw source.

**Key constraints:**

- Works on `file://` and HTTP equally — `js/file-protocol-fix.js` patches `localStorage` for `file://` origins
- 93 `<script>` tags in `index.html` (88 with `defer`) — load order is strict and intentional; `init.js` stays **last** (any feature script, e.g. `spot-ratio-math.js`/`spot-ratio-chips.js`, loads before it)
- New JS files must be registered in **both** `index.html` (as `<script defer>`) and `sw.js` `CORE_ASSETS`
- All DOM access outside `about.js`/`init.js` must use `safeGetElement(id)`, not `document.getElementById()` — narrow exception: a **create-if-missing singleton** (e.g. `getRatioChipTip()` in `spot-ratio-chips.js`) uses `document.getElementById` on purpose, since `safeGetElement` returns a truthy dummy on a miss and would make the "not found → create it" branch unreachable; second exception: **`events.js` top-level parse-time wiring** must use `document.getElementById` — `safeGetElement` is defined in `init.js`, which loads last, so calling it at parse time throws a silent ReferenceError (see `.context/implementation-gotchas.md`)
- All localStorage writes must use `saveData()`/`saveDataSync()` from `js/utils.js` — never raw `setItem`
- All localStorage keys must be declared in `ALLOWED_STORAGE_KEYS` in `js/constants.js`
- API settings panel uses a single-select `spotPricingSource` (6 options: STAKTRAKR, METALS_DEV, METALS_API, METAL_PRICE_API, CUSTOM, MANUAL) instead of fallback-chain provider priority — see API Settings Tab for detail

### Boot Dispatch — Inventory Seed Guard (STRK-13)

`init.js` Phase 12 no longer unconditionally seeds inventory. Before `await loadInventory()` runs, `classifyBootState()` (in `js/seed-data.js`) snapshots `localStorage` and returns one of four classifications plus a `keyPresence` map:

| Classification        | Trigger                                                                                                                                       | Action                                                                                  |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `first-run`           | No `metalInventory`, no prior-user evidence keys, no `inventorySeedApplied` sentinel                                                          | `loadSeedInventory(stateResult)` — writes 8 sample items + sentinel                     |
| `returning-with-data` | `metalInventory` parses to a valid array (any length, including empty)                                                                        | `migrateSentinelIfMissing(stateResult)` — back-fills sentinel if absent, never re-seeds |
| `damaged-key`         | `metalInventory` missing AND any of `inventorySerial` / `cloud_sync_local_modified` / `cloud_sync_device_id` / `inventorySeedApplied` present | `showInventoryRecoveryBanner({cloudConnected})` + `setInventoryRecoveryActive(true)`    |
| `parse-error`         | `metalInventory` exists but unparseable / non-array (after `__decompressIfNeeded`)                                                            | Same as `damaged-key`; entry recorded with `errorName`                                  |

Every boot also calls `recordBootDiagnostic({classification, keyPresence, errorName?})` regardless of branch — see #Storage Layer.

**Classification runs BEFORE `loadInventory()`** (deviation from the original design plan): `loadInventory()` writes `inventorySerial` early via `getNextSerial()`, which on a brand-new origin would otherwise trip the `damaged-key` branch.

**`inventoryRecoveryActive` flag** (module-scoped in `js/inventory.js`, mirrored on `window`): when `true`, `saveInventory()` early-returns so a corrupt `metalInventory` key cannot be silently overwritten with `[]`. Cleared by any explicit user action (add item, CSV/JSON/Numista import, vault or cloud restore, banner _Dismiss_ / _Open Cloud Settings_).

For full file:line traceability see STRK-13 verification and the Plane issue at <https://plane.lbruton.cc/lbruton/browse/STRK-13/>.

### Weight Units and Valuation

The item data model uses `weightUnit` to decide whether `weight` is already fine troy ounces or needs conversion before valuation:

| Unit                  | Meaning                                                                   | Conversion                                                                  |
| --------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `oz`, `g`, `kg`, `lb` | Standard bullion weight entry modes                                       | Normalized to troy ounces before valuation                                  |
| `gb`                  | Goldback denomination count                                               | `weight * GB_TO_OZT`                                                        |
| `sb`                  | Silverback unit count                                                     | `weight * SB_TO_OZT`                                                        |
| `cu`                  | Constitutional / junk-silver inputs (denomination + count, or face value) | `getConstitutionalSilverOz(item)` — already pure, qty-folded, wear-adjusted |

Goldbacks are the only type eligible for the Goldback denomination retail-price path. Silverbacks use the dedicated `sb` unit and fall through to melt-based retail valuation (`weight * SB_TO_OZT * spot * purity`). Legacy Silverback records that were stored as `weightUnit: "gb"` are migrated to `sb` during load, import, encrypted backup restore, and cloud restore preview paths.

**Constitutional / junk silver (`cu`, STRK-235, v3.35.50).** U.S. 90% / 40% / 35% coinage entered by _denomination + coin count_ or _total face value_. Like `gb`/`sb` it uses deferred conversion — the item stores inputs, not troy oz — but unlike them the derived figure is **already pure silver**, so `computeMeltValue()` early-returns `getConstitutionalSilverOz(item) * spot` and never re-applies `purity`. See [Constitutional Silver Unit Conversion](#constitutional-silver-unit-conversion).

### Service Worker (`sw.js`)

- Pre-caches ~118 `CORE_ASSETS` on install (includes the `/ratios/` shell, its manifest, `js/ratios-page.js`, and the ratios icon set since STRK-274)
- Purges old caches (`staktrakr-*`) on activate
- Routing: `file://` bypassed; MetalPriceAPI/Numista = network-first; CDN = stale-while-revalidate; `api.staktrakr.com`/`api2.staktrakr.com` = classified — realtime price families (`spot-latest`/`goldback-latest`/`retail-latest`) **network-first**, other families cache-first-with-TTL (STRK-249; see `coding-standards.md` §Classified caching); local JS/CSS = network-first; navigation = network-first with **per-shell nav caching**
- **Per-shell navigation cache (STRK-273/274):** `navShellCacheKey()` in `sw-router.js` maps navigations to shell cache keys — tracker → `"./"`, `/ratios/` (incl. bare `/ratios`) → `"./ratios/"`, every other same-origin page → `null` (bypasses the nav cache in both directions, receiving honest error/offline responses). Before this guard, ANY same-origin navigation overwrote the cached tracker shell.
- `CACHE_NAME` auto-stamped by `devops/hooks/stamp-sw-cache.sh` pre-commit hook — never edit manually

## API Layer

### Base URLs

| Role | URL                          | Host                                               |
| ---- | ---------------------------- | -------------------------------------------------- |
| api1 | `https://api.staktrakr.com`  | GitHub Pages (`lbruton/StakTrakrApi` `api` branch) |
| api2 | `https://api2.staktrakr.com` | Fly.io machine (see `infrastructure.md`)           |

**Endpoint selection is freshest-wins, not primary/fallback (STRK-331, v3.35.96–98).**
The spot sync (`_fetchFreshestSpotEnvelope`, `js/api.js`) and the retail market sync
(`_pickFreshestV2Endpoint`, `js/retail.js`) fetch every endpoint in parallel and use the
one with the newest `generated_at`; ordered try-each failover (`_staktrakrFetch`) remains
for single-file fetches (hourly spot backfill, year-history files). Every candidate still
passes the STRK-189 freshness gate (rejects stale SW/CDN copies; all-stale fails the sync),
the per-fetch 5 s timeout covers headers _and_ body, and the footer health badge reports
the same freshest-per-feed age with a separate infra icon (✅/⚠️). Do not add manual
switching logic, and do not reintroduce order-based preference.

### v1 vs v2

v2 API (STAK-503) was introduced behind a feature flag, shipped as default in STAK-506, and v1 was fully removed in STAK-509 (v3.33.92). **v2 is the sole API layer.** v1 endpoints (`data/api/`) are no longer referenced by frontend code. All frontend fetches now target `data/v2/`.

### v2 Endpoints

All v2 endpoints live under `data/v2/` and use a self-describing envelope:

```json
{
  "v": 2,
  "generated_at": "2026-03-25T14:08:01.756Z",
  "stale_after": 1800,
  "data": { ... }
}
```

| Endpoint                                 | Description                                                          | Stale After     |
| ---------------------------------------- | -------------------------------------------------------------------- | --------------- |
| `data/v2/manifest.json`                  | Coin list, endpoint templates, stale thresholds                      | 1800 s (30 min) |
| `data/v2/spot/latest.json`               | Current spot prices (4 metals) with OHLCA aggregates                 | 1200 s (20 min) |
| `data/v2/retail/{slug}/latest.json`      | Per-coin vendor prices with carry-forward metadata                   | 1800 s          |
| `data/v2/retail/{slug}/history-7d.json`  | 7-day daily OHLCA aggregates                                         | 1800 s          |
| `data/v2/retail/{slug}/history-30d.json` | 30-day daily OHLCA aggregates                                        | 1800 s          |
| `data/v2/retail/{slug}/history-90d.json` | 90-day daily OHLCA aggregates with per-Vendor averages               | 86400 s (24 h)  |

### API Consumption Pattern

`_staktrakrFetch(urls, path)` tries each URL in order with a 5 s `AbortController` timeout. Do not wrap in additional retry logic — it already iterates `baseUrls`.

Frontend v2 data flow:

1. `fetchStaktrakrPrices()` → `v2/spot/latest.json` — extracts prices from OHLCA `close` fields
2. `syncRetailPrices()` → `v2/manifest.json` then per-slug `v2/retail/{slug}/latest.json`
3. `fetchGoldbackApiPrices()` → `v2/goldback/latest.json`
4. `fetchApiHealth()` → reads `stale_after` from v2 envelope, not hardcoded thresholds
5. `market-data.js` → reads `retailPrices` and `v2SpotHistory` from localStorage; makes no API calls itself

## Data Model

### Portfolio Value Model (Three Dimensions)

| Dimension      | Source             | Stored?                             | Formula                          |
| -------------- | ------------------ | ----------------------------------- | -------------------------------- |
| Purchase Price | User entry         | Yes — `item.price` (per-unit)       | —                                |
| Melt Value     | Computed at render | **No**                              | `weightOz × qty × spot × purity` |
| Retail Price   | Live API ask       | No — cached in `retailPrices[slug]` | —                                |

`meltValue` is **never stored**. Spot moves constantly; deriving at render keeps stored schema simple. `realizedGainLoss` is the sole exception — computed once at disposition time and stored.

`item.price` remains a **per-unit USD purchase price** even when the UI accepts a lot total. STRK-4's Lot/Each purchase-price toggle divides lot input by quantity before the existing display-currency to USD conversion path persists the item; table and modal total displays derive from `item.price * qty` and do not change the stored schema. STRK-68 added `pricingType: "each" | "lot"` to record which mode the user chose; the price history chart uses it to scale purchase, melt, and retail lines consistently. STRK-242 promoted `pricingType` from a presentation-only chart hint to a **load-bearing** field for constitutional ("cu") by-denomination items: it drives edit-restore (reopening a saved item in LOT vs EACH) and is registered for persistence on JSON export/import, ZIP backup, and cloud-sync (cu-scoped hash / `DIFF_FIELDS` / change-log). Cost basis still rides on `price × qty` on every path regardless. For cu by-denomination, the entered lot total divides by the **coin count** (`cu.qty`), not `#itemQty` (pinned to 1 for cu); by-face-value is a lot of one (no division). Legacy items without `pricingType` default to lot-total display (chart) and EACH (cu edit-restore).

### Goldback Unit Conversion

```js
GB_TO_OZT = 0.001; // 1 Goldback denomination = 0.001 troy oz of 24K gold
// When item.weightUnit === 'gb':
const weightOz = item.weight * GB_TO_OZT;
```

### Constitutional Silver Unit Conversion

Constitutional ("junk") silver (`weightUnit: "cu"`, STRK-235) uses **deferred conversion** mirroring the Goldback/Silverback pattern — the item stores user inputs (a `constitutionalVariant` + coin count, _or_ a face value) and the troy-oz figure is derived on demand:

```js
// getConstitutionalSilverOz(item) — js/utils.js
// Returns TOTAL pure silver troy oz: qty is folded in, the worn/fresh wear factor
// is applied, and the result is ALREADY PURE. Callers must NOT × qty or × purity.
//   face mode:  item.weight ($face) × CONSTITUTIONAL_SUBSIDIARY_OZT_PER_DOLLAR × wear
//   denom mode: variant.silverOzFresh × wear × qty
// computeMeltValue() early-returns for cu:  getConstitutionalSilverOz(item) × spot
```

**`CONSTITUTIONAL_VARIANTS` (7 variants):** 90% dime / quarter / half + Morgan/Peace dollar, 40% Kennedy half (1965–70) + 40% Ike dollar, 35% war nickel (1942–45).

- **Silver-dollar exception:** Morgan/Peace dollars carry ~0.7734 ozt/coin, **not** the 0.7234 oz/$ subsidiary rate — a generic "90% → 0.7234/$" branch undervalues every silver dollar.
- **No double-purity:** the variant figures are already pure silver, so the `cu` branch returns before the `× purity` multiply. `$10` face 90% subsidiary (worn) ≈ 7.15 ozt × spot.
- **Worn vs fresh basis:** a single global wear multiplier (`CONSTITUTIONAL_BASIS_KEY`, default `"worn"`) applied to fresh ASW, persisted and cloud-synced; toggling it reprices the table without per-item edits.
- **Enum-id integrity:** `sanitizeObjectFields()` must **not** strip hyphens from the `constitutionalVariant` id (e.g. `con-90-quarter`) on load/import — the STRK-235 fix exempts it.

### Disposition Record

Written to `item.disposition` when an item is sold/disposed. Never re-derived after write.

```js
{
  type:             String,    // "sold" | "traded" | "lost" | "gifted" | "returned"
  date:             String,    // "YYYY-MM-DD"
  amount:           Number,    // USD received (0 for lost/gifted)
  realizedGainLoss: Number,    // amount - (price * qty) — computed once at disposition
  disposedAt:       String,    // ISO timestamp (doubles as transactionId for paired log entries)
  splitFromUuid?:   String,    // UUID of source stack — present only on partial-stack clones (STRK-44)
}
```

`isDisposed(item)` in `js/constants.js` is the **single source of truth** for disposition validity: it returns `true` only when `item.disposition` is a non-null, non-array object with at least one own key (an empty `{}` is **not** disposed — a Disposition records realized value and date). Disposed items are excluded from active portfolio totals but tracked separately in `updateSummary()`.

**Single source of truth (STRK-83):** every disposed/active decision routes through `isDisposed()` — the disposed filter (`js/filters.js`), summary totals, row/card styling + badge, the trade-link guards (`js/inventory.js`), the trade autocomplete, and `_buildDispositionSection()`'s render guard (`js/viewModal.js`). The earlier STRK-73 predicate inconsistency (a loose truthy `isDisposed()` vs the tighter empty-object guard in `_buildDispositionSection()`) is resolved: an item with `disposition: {}` is now treated as not disposed everywhere. The only deliberate exception is the defensive `source.disposition || {}` provenance fallback in `js/viewModal.js`, which is a no-data default, not a disposed/active decision.

**Partial-stack splits (STRK-44):** When `disposedQty < stackQty`, the original record is decremented in place (no disposition set) and a `structuredClone` is inserted at `idx + 1` with `qty = disposedQty`, a fresh `uuid` + `serial`, and a disposition containing `splitFromUuid`. Two correlated Activity Log entries share the same `transactionId` (the `disposedAt` ISO timestamp) and undo atomically via `confirmCascadeUndo`. Restoring a split clone prompts merge-or-separate.

### Storage Layer

| API               | Function                                                  | Use When                           |
| ----------------- | --------------------------------------------------------- | ---------------------------------- |
| Async (preferred) | `saveData(key, value)` / `loadData(key, default)`         | Large JSON payloads, LZ-compressed |
| Sync              | `saveDataSync(key, value)` / `loadDataSync(key, default)` | UI preferences, non-blocking reads |

Both transparently handle lz-string compression (real `compressToUTF16`, `CMP2:` prefix; legacy `CMP1:` read-only — see coding-standards.md). `loadData`/`loadDataSync` return `defaultValue` on missing or corrupt keys — never throw.

All keys registered in `ALLOWED_STORAGE_KEYS` (`js/constants.js`). `cleanupStorage()` at startup silently deletes any key not in the allowlist. The allowlist is enforced at **startup** (cleanup), not at **write time** — unregistered keys write successfully but are deleted on next load.

### IndexedDB Stores

Three IndexedDB databases persist data that exceeds localStorage's ~5 MB ceiling:

| Database                  | Store             | Key                  | Purpose                                                                            | Module                     |
| ------------------------- | ----------------- | -------------------- | ---------------------------------------------------------------------------------- | -------------------------- |
| `StakTrakrImages` v1      | `userImages`      | `itemUuid`           | Obverse/reverse custom photos (base64 data URIs)                                   | `js/image-cache.js`        |
| `StakTrakrAttachments` v1 | `userAttachments` | `attachmentUuid`     | Receipts, COAs, dealer invoices (Blob binary) — per-item, multiple files (STRK-45) | `js/attachment-manager.js` |
| `StakTrakrHistory` v1     | `histories`       | `key` (logical name) | Spot + retail market history blobs (STRK-141, v3.35.3)                             | `js/history-store.js`      |

All three databases use the same `_ensureDb` + singleton pattern. `attachmentManager` is exposed as `window.attachmentManager`; `imageCache` as `window.imageCache`; `historyStore` as `window.historyStore`.

**`StakTrakrHistory` history record schema** — a single coarse-grained `histories` store, one record per logical history (not per entry):

```js
{
  key:       String,   // logical history name: "metalSpotHistory" | "v2RetailHistory" | (future: goldback)
  data:      any,      // decompressed JSON blob — spot = entries array; retail = { [slug]: entry[] }
  updatedAt: Number,   // epoch ms, set on each put (diagnostics / settings panel)
}
```

`metalSpotHistory` (spot price time series) and `v2RetailHistory` (daily retail history per slug) now live here, **not** in localStorage — so they no longer consume the localStorage budget. IndexedDB stores them **uncompressed** (the Phase-1 LZ compression existed only to fit the localStorage ceiling; pointless at ~4 GB headroom). A one-time, idempotent boot migration (`historyStore.migrate()`, flag `migration_idb_history_v1`) copies any legacy localStorage payloads — including Phase-1 `CMP2:`-compressed ones — into IDB, deleting the legacy copies **only after** a confirmed IDB write. If IndexedDB is unavailable, the app transparently stays on localStorage (the spot/retail keys remain in `ALLOWED_STORAGE_KEYS` to protect the fallback). `item-price-history` is the one market history that **stays in localStorage**, now bounded by a silent retention cap (365 days / 1000 entries per item).

**Attachment record schema** (stored in IDB, not in localStorage):

```js
{
  attachmentUuid: String,   // UUID v4 primary key
  itemUuid:       String,   // parent inventory item UUID
  fileName:       String,   // original filename
  mimeType:       String,   // "application/pdf" | "image/jpeg" | "image/png"
  size:           Number,   // bytes
  uploadedAt:     String,   // ISO 8601 timestamp
  blob:           Blob,     // binary content
}
```

The item record's `attachments` array carries metadata only (no `blob`). The IDB record carries the `blob`. A missing IDB binary while metadata exists is the "missing-binary" state — the item remains valid, the attachment badge shows but download fails gracefully.

## Provider/Vendor Data Model

Provider data (which vendors to scrape, URLs, coin metadata) lives exclusively in sqld (`provider_coins` and `provider_vendors` tables). The static `providers.json` on the `api` branch is **auto-generated** from sqld every publish cycle — direct edits are overwritten.

### provider-db.js (shared module)

Lives at `devops/pollers/shared/provider-db.js`. Both pollers' Dockerfiles `COPY shared/*.js` — no manual sync. Key operations:

| Function                                                  | Description                                          |
| --------------------------------------------------------- | ---------------------------------------------------- |
| `getProviders(client)`                                    | Full coin+vendor config map                          |
| `loadProviders(client, dataDir)`                          | sqld-first with local `providers.json` file fallback |
| `exportProvidersJson(client)`                             | Generates `providers.json` for the `api` branch      |
| `getVendorScrapeStatus(client)`                           | Latest scrape result per vendor (window function)    |
| `getCoverageStats(client, hours?)`                        | Hourly coverage percentage — used by dashboard       |

### Fallback Strategy

`loadProviders(client, dataDir)`:

1. Tries `getProviders(client)` from sqld
2. On failure, falls back to `loadProvidersFromFile(dataDir)` — reads local `providers.json`
3. Logs which path was taken

### Slug Resolution and Market Filter

`getActiveRetailSlugs()` in `js/retail.js` is the single chokepoint for all downstream slug consumers. It applies `_isSlugResolved(slug)` upstream — only slugs where `meta.name !== slug && meta.metal !== "unknown"` pass through.

All downstream components (market cards, Best Price Ticker, Vendor Prices table, Market Filter Matrix in Settings) read from `getActiveRetailSlugs()`. Do not re-filter downstream — add new predicates inside `getActiveRetailSlugs()`.

The market filter (`MARKET_FILTER_KEY` localStorage key) stores a `slug → vendor → boolean` map. Absent entries default to enabled (no filter = show everything). `_loadMarketFilter()` normalizes corrupted entries (STAK-520) and deletes persisted entries for slugs that fail `_isSlugResolved` (STAK-540).

After a vault restore or cloud sync pull that writes `staktrakr.market_filter`, `restoreVaultData()` automatically calls `_invalidateMarketFilterCache()` and `renderMarketFilterMatrix()` so the Market Filter Matrix in Settings reflects the restored state without a page reload (STAK-517).

### API Health

`initApiHealth()` (called by `init.js`) probes all three feeds in parallel via `fetchApiHealth()`. Health badge reads `generated_at` from v2 envelopes for staleness — not `scraped_at`. Stale thresholds: market = 30 min, spot = 20 min, goldback = 2 h (STRK-248; was 25 h).
